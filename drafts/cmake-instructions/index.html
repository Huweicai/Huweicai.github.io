CMake

CMake 现在已经是 mordern c++ 项目中事实上的建构标准了，但是其本质上其实就是一个 Makefile 生成器，只是在 Makefile 之上引入了一层抽象，帮我们解决了很多直接编辑 Makefile 不太方便的地方，比如更友好的指令、跨平台支持、更灵活的条件循环语句以及其他功能性拓展等等，但是这层抽象有时候又会屏蔽一些本来底层非常简单的事情，引入一层新的复杂度，因此了解 CMake 常见的一些指令的底层工作原理可以帮助开发者更好地使用和定制 CMake，充分发挥其优势，并解决可能出现的问题。

常见指令

find_package

find_package()

include_directories

这个指令非常简单直接，指令格式：include_directories(dir1 [dir2 ...])

接收一个或多个目录做为入参，并将这些目录全部展开为绝对目录，然后 CMake 会将这些目录拼接出-I（头文件搜索路径）选项列表，传给 g++、clang++ 等编译工具，这样编译器编译的时候就会去这些路径内查找头文件。

include_directories是全局的，当前 List 文件中所有的 target ，都会加上申明的搜索路径，也会对子项目生效，但是子项目的 include_directories 。

这个指令可以出现多次，后出现的目录会被追加到 -I 列表后面，不过也可以通过申明BEFORE来让路径插在前方，来让编译器优先搜索该路径，像这样：

include_directories(BEFORE ${CMAKE_SOURCE_DIR}/include)

最终生成的 -I参数列表我们可以在 CMakeFiles/${TARGET}.dir/flags.make中的 CXX_INCLUDES 变量找到。

target_inlucde_directories

因为include_directories是全局的，无法精确为每个 target 生成 -I选项，所以在 2.8.11 版本引入了 target_include_directories，顾名思义就是能为特定的 target 指定头文件搜索路径。

同时还加入了一些额外的特性，可以指定 include 的生效范围，可以指定 scope 为：

  • PRIVATE：只为当前 target 添加头文件搜索路径，即使有 target 依赖了当前 target 也不会添加
  • INTERFACE：只为依赖 target 添加
  • PUBLIC：当前 target 和依赖 target 都会添加

link_directories

这个指令和 include_directories，也是接收目录参数，然后拼接出 -L选项列表指示链接器去这些目录下搜索库文件进行链接。

同样的也支持申明 BEFORE or AFTER来指定 -L 列表的顺序。

但是 link_directories和 include_directories有个很大的不同之处在于，link_directories只对在其之后申明的编译目标生效，例如在下面的例子中是不会为 demo1 生成 -Llib参数的：

add_executable(demo1 main1.cpp)

link_directories(lib)

add_executable(demo2 main2.cpp)

可能是 CMake 希望大家减少依赖到错误库的可能吧，毕竟相对于编译异常而言，链接时的异常通常更加隐晦和危险。
