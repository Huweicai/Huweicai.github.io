OPEN

在开始读取一个文件之前，我们需要先打开它，在 linux 下，这个操作是由 open 系统调用完成的。

用户态的封装函数 open() 可以在 fcntl.h头文件中找到，函数原型：

int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);

open 存在两个重载函数，三个入参：pathname、flags、mode。

pathname 代表要打开的文件路径；

flags 是一组文件操作标志位，多个标志位之间通过或运算连接，必须包含访问模式中的其中一个：

  • O_RDONLY 只读
  • O_WRONLY 只写
  • O_RDWR 读写

以及其他的一些可选的标志位，常见的有这些：

  • O_APPEND每次写入都会从文件最末尾开始追加
  • O_CREAT如果 pathname 对应的路径不存在则创建一个，同时 mode 参数会做为该文件的初始访问权限模式传入，比如：777 （全局可读）
  • O_DIRECT 直接读写设备不走内核缓存
  • O_TMPFILE创建一个临时文件，在文件描述符关闭时就会被删除

open 调用的出参是一个非负数字，文件描述符（file descriptor: fd），每个进程会有一个数组存储了其打开文件的数据结构，fd 就是该打开文件在这个数组中的索引。

用户态 READ

open()了一个文件之后，我们就可以调用 read() 来读取对应文件中的数据了。

read()用户态函数的定义是在各个 C 标准库中内置的，以应用最为广泛的标准库 glibc 为例，其定义于 unistd.h 头文件中，签名如下：

# fd 即为 open 得到的文件描述符
# buf 是用于存放读到数据的缓冲区
# nbytes 指定要读取多少个字节
# 出参为此次 read() 之后读到多少个字节
ssize_t read (int __fd, void *__buf, size_t __nbytes)

查看 glibc源代码我们不难发现，标准库对于该调用的实现非常简单， sysdeps/unix/sysv/linux/read.c:23：

/* Read NBYTES into BUF from FD.  Return the number read or -1.  */
ssize_t
__libc_read (int fd, void *buf, size_t nbytes)
{
  return SYSCALL_CANCEL (read, fd, buf, nbytes);
}

只是对于系统调用的简单封装，SYSCALL_CANCEL宏允许调用线程在终止时也同时终止该系统调用，避免无效的资源浪费。

系统调用 READ

Linux 操作系统中系统调用的入口配置在 syscall_64.tbl 文件中，它会在编译的时候展开成对应的处理代码。

其中第一行便是我们要找的 read系统调用：

0	common	read			sys_read
1	common	write			sys_write
2	common	open			sys_open
3	common	close			sys_close
4	common	stat			sys_newstat
...

由该表可知，read() 系统调用对应的处理入口函数是 sys_read()，而这一系列 sys_ 开头的入口函数，都是通过 SYSCALL_DEFINE宏定义生成的，它会针对传入的 name参数扩充出一个名为sys_name对应的函数实现。

sys_read()的实现定义于read_write.c#L621，它又调用了 ksys_read() 函数，这才是真正内核处理逻辑的开始。
